# Лавка героя: пишем unit-тесты

Задание к уроку 17 «Unit-тесты на pytest». В проекте есть готовая бизнес-логика «Лавки героя», но **нет ни одного теста**.
Твоя задача — покрыть её unit-тестами, найти спрятанную ошибку и написать новую функцию через TDD.

## Как запустить

Нужен [uv](https://docs.astral.sh/uv/).

```shell
uv sync --group test
uv run pytest -v             # тесты
make quality_assurance       # ruff + mypy + тесты
```

Пока тестов нет, `pytest` ответит `no tests ran`, а `make quality_assurance` упадёт на этом шаге. Это нормально:
после первой задачи всё станет зелёным.

## Что лежит в проекте

| Файл | Что делает |
|---|---|
| [`src/utils/slug.py`](./src/utils/slug.py) | `slugify`: «Деревянный меч» → `derevyannyy-mech` |
| [`src/utils/inventory.py`](./src/utils/inventory.py) | `split_into_stacks`: раскладывает предметы по ячейкам рюкзака: 45 стрел по 20 → `[20, 20, 5]` |
| [`src/service/shop/cart.py`](./src/service/shop/cart.py) | `CartService.calculate`: сумма корзины, скидка по промокоду, доставка (бесплатно от 100 золотых **после** скидки, иначе 15) |
| [`src/const/promo_code.py`](./src/const/promo_code.py) | промокоды: `HERO10` — 10 %, `DRAGON25` — 25 % |
| [`src/utils/words.py`](./src/utils/words.py) | `coins_word`: «1 монета, 2 монеты, 5 монет». **В ней спрятана ошибка** |

Ручки (`src/route/`) и `main.py` в этом задании не тестируем: для них нужны интеграционные тесты (урок 19).

## Правила

- Тесты — в папке `tests/unit_tests`, файлы `test_*.py`, структура повторяет `src/`:
  тесты `src/service/shop/cart.py` — в `test_cart_service.py`.
- Тесты одного класса или модуля можно собрать в класс: `class TestCartService:`.
- Один тест — одно поведение, имя теста — фраза о поведении: `test_delivery_is_free_from_100`.
- У тестов подписаны типы (`-> None`): `mypy --strict` проверяет и `tests`.
- Каждый новый тест один раз **сломай** (поменяй ожидаемое значение) и убедись, что он падает.
- Тесты не должны зависеть друг от друга и от порядка запуска.
- После каждой задачи — `make quality_assurance`.

## Задачи

### 🟢 1. Первые тесты

Напиши тесты:

- `slugify` на два-три обычных названия;
- `split_into_stacks` на случаи «с остатком», «ровно», «меньше одной ячейки», «ноль предметов» и «размер ячейки 1» —
  **одним параметризованным тестом с `ids`**; отдельно — размер ячейки по умолчанию;
- `CartService.calculate`: сумма с учётом количества, платная и бесплатная доставка, промокод, неизвестный промокод
  (`BadRequestException` с кодом 400 и текстом `Unknown promo code: FREE100`).

*Подсказка:* напиши вспомогательную функцию, которая собирает корзину из цен, например `make_cart(40, 60, promo_code='HERO10')`.

### 🟢 2. Ошибки и границы

- `slugify`: пустая строка и строка из одних знаков препинания (обе дают `item`), цифры («Меч +3» → `mech-3`),
  латиница, заглавные буквы и «Ё». Параметризованно, с `ids`.
- `split_into_stacks`: отрицательное количество и размер ячейки 0 или меньше — `ValueError` с правильным текстом
  (`pytest.raises` с `match`).

### 🟡 3. Границы корзины

Одним параметризованным тестом проверь `subtotal`, `discount`, `delivery` и `total` для случаев:

- 99, 100 и 101 золотой без промокода;
- 120 золотых с `DRAGON25` (скидка считается до доставки);
- 25 и 35 золотых с `HERO10`. Посчитай скидку на бумаге до запуска.

*Подумай:* 10 % от 25 — это 2,5. Какую скидку дала программа и почему?

### 🟡 4. Найди ошибку

В `coins_word` есть ошибка. Напиши параметризованный тест на числа, которые кажутся тебе важными, найди ошибку
**тестом**, потом исправь функцию. Тест должен упасть до исправления и пройти после.

*Подсказка:* «11 монет» или «11 монета»? А «111»?

### 🔴 5. Сначала тест (TDD)

Нужна функция `hero_level(xp)` в `src/utils/level.py` — уровень героя по опыту:

- на уровне 1 опыта 0, для уровня 2 нужно 100, для 3 — 300, для 4 — 600: каждый следующий уровень на 100 опыта дороже предыдущего;
- максимальный уровень — 50;
- отрицательный опыт — `ValueError` с текстом `xp can't be negative`.

Порядок обратный: **сначала** параметризованный тест со всеми важными случаями (0, 99, 100, 299, 300, очень большой опыт),
убедись, что он падает, и **только потом** функция.
